# Vaultmarks Full Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Vaultmarks one identity across the app icon, Chromium extension, Obsidian viewer and GitHub repository, and make the README show the desktop-capture / phone-reading story.

**Architecture:** Brand assets are static SVG/PNG files under `docs/brand/`, built once and committed. The extension changes only CSS custom properties; the viewer changes only its colour constants plus one dark surface on `dv.container`. Screenshots come from committed Playwright harnesses that drive the real extension page and the real viewer block with fixture notes.

**Tech Stack:** Chromium extension (MV3, no build), plain CSS, DataviewJS, Node `node:test`, Playwright (external, not a package dependency), `rsvg-convert`, fontTools in a temporary venv for wordmark outlines.

**Spec:** `docs/superpowers/specs/2026-11-20-branding-design.md`

## Global Constraints

- No build step and no new `package.json` dependency; Playwright is resolved from an environment path or a global install.
- No runtime web font; every line of text in `banner.svg` and `social-preview.svg` is outlined, with no `<text>` element.
- Palette: Ink 950 `#0c0a14`, Ink 900 `#14101f`, Ink 850 `#1b1730`, Ink 800 `#241d3d`, UI dark `#14111d`, viewer card `#161226`, viewer panel `#100c1e`, Violet 300 `#c4b5fd`, Violet 400 `#a78bfa`, Violet 500 `#8b6ef5`, Violet 600 `#6d4ae0`, Violet 700 `#5a3fd1`, paper `#f7f5fb`, success teal `#2dd4bf`.
- Extension light tokens: `--bg #ffffff`, `--fg #1b1726`, `--muted #6b6478`, `--line #e7e2f0`, `--accent #6d4ae0`, `--accent-fg #ffffff`, `--surface #f8f6fc`, `--hover #f1edf9`.
- Extension dark tokens: `--bg #14111d`, `--fg #ece9f5`, `--muted #a49db8`, `--line #322b45`, `--accent #a78bfa`, `--accent-fg #14101f`, `--surface #1d1829`, `--hover #262033`.
- Viewer constants: `cardBg #161226`, `leftPanelBg #100c1e`, border `rgba(167, 139, 250, 0.32)`, title `#c4b5fd`, description `#d7d3e3`, url `#a78bfa`, domainLabel `#a78bfa`, highlight `rgba(196, 181, 253, 0.32)`, page `#14101f`.
- Banner `1600×400`; social preview `1280×640`; panel capture `780×600` at 2× (`1560×1200`); phone capture `390px` wide at 2×.
- No layout, markup or behaviour changes beyond the viewer's dark surface.
- No licence, landing page, Chrome Web Store copy, or new features.
- Commit and push to `main`; sync `/tmp/opencode/vaultmarks`; the live viewer and `obsidian/vaultmarks.md` stay byte-identical.
- Every text pair reaches 4.5:1; UI borders and focus rings 3:1.

## Review Focus

- **Light Obsidian theme.** The viewer's headings, tree and status line must stay readable on a white page; the block paints its own dark surface. Test: `viewer paints a dark surface for text outside cards` in Task 3.
- **GitHub SVG without fonts.** Banner and social preview must render identically on GitHub and in `rsvg-convert`; all text is outlined. Test: `brand SVGs contain no text elements` in Task 1.
- **Contrast in both extension schemes.** Violet accents can fail on light or dark surfaces. Test: `brand token pairs meet WCAG AA` in Task 2.
- **Live viewer safety.** Syncing and recolouring must not drop the icon fallback, lazy covers, edit-in-new-tab or Markdown-safe writes. Test: `repo viewer matches the live note and keeps recent behaviour` in Task 3.
- **Screenshot honesty.** The panel must be the real page, not a mock. Test: `README screenshots exist at their declared sizes` in Tasks 4–6, plus visual review of the captured page.

- [ ] **Step 3: Outline the wordmark**

Use a temporary venv; do not add a dependency to the repo.

```bash
python3 -m venv /tmp/opencode/brandenv
/tmp/opencode/brandenv/bin/pip install fonttools
curl -L -o /tmp/opencode/SpaceGrotesk.ttf \
  "https://github.com/google/fonts/raw/main/ofl/spacegrotesk/SpaceGrotesk%5Bwght%5D.ttf"
```

Instantiate weight 600, map the string `Vaultmarks` through the cmap, and write each glyph with `fontTools.pens.svgPathPen.SVGPathPen`. Flip the font's y-up coordinates with `translate(0, ascent) scale(size/upem, -size/upem)` and advance x by each glyph's `hmtx` advance plus `-0.03em` tracking. Keep the result in a `<g>` labelled `wordmark`; the same routine produces the tagline at weight 500 and the three labels at weight 500. The font file is never committed.
